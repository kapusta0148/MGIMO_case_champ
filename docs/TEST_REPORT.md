## Что покрывают серверные тесты (backend/tests)

- **Вход и сессии (`test_auth.py`):** верный и неверный пароль дают одинаковый ответ для существующего и несуществующего логина; без CSRF-токена вход и изменения отклоняются (403); после выхода все личные адреса отвечают 401; сохранённая до выхода cookie не работает; сессия истекает через 7 дней; отключённый пользователь теряет доступ; пароли хранятся как `$argon2id$` с разной солью; после 5 неверных паролей — 429 с `Retry-After`, другой логин не блокируется; флаги `HttpOnly`, `SameSite=Lax`, `Secure` (в режиме HTTPS).
- **Чужие данные (`test_access_control.py`):** второй студент получает 404 на чужую заявку, её комментирование, чужие уведомления, занятия и дедлайны другой группы, объявления для другого факультета; перебор номеров заявок ничего не раскрывает; подмена `user_id`/`ownerUserId`/`status` в теле или параметрах запроса игнорируется; деканат, преподаватель и администратор получают 403 в кабинете студента.
- **Разделы студента (`test_student_views.py`):** профили двух студентов различаются; «Сегодня» — текущая и следующая пара, перенос, ближайший дедлайн, активная заявка; расписание на день и неделю; **перенос — одна и та же запись на «Сегодня», в уведомлении, по ссылке и в расписании**; повторный перенос обновляет то же уведомление; перенос на другой день оставляет след на исходном; занятое время и неверный ввод отклоняются; отменённая пара не считается следующей; шкала оценок; экзамен / зачёт / «ожидается»; разные оценки у студентов; демо-перенос находится и в субботу вечером.
- **Заявки (`test_requests.py`):** создание, сохранение после выхода и входа с другого устройства, 12 вариантов неверной формы с сообщениями по полям, повторная отправка с тем же ключом не создаёт дубль, HTML в тексте хранится как текст, история статусов и уведомление владельцу, невозможные переходы статуса, ответ на «требует уточнения», лимит открытых заявок.
- **Платформа (`test_notifications_and_platform.py`):** все ссылки уведомлений открывают свой объект, «прочитано» сохраняется, напоминания о дедлайнах не дублируются, заголовки `no-store` и `nosniff`, единый формат ошибок, 500 без технических подробностей, **миграции с нуля совпадают с моделями**.

## Что покрывают сквозные тесты (frontend/e2e)

1. Вход → «Сегодня» → уведомление о переносе → то же занятие подсвечено в расписании с тем же временем и аудиторией → заявка (сначала пустая форма с ошибкой, потом верная) → обновление страницы → выход → прямой адрес заявки ведёт на вход → после входа возврат на эту заявку.
2. Второй студент в отдельном браузерном контексте: свой профиль и оценки, чужой заявки нет в списке, по прямому адресу — «Заявка не найдена», API — 404.
3. Десять экранов без горизонтальной прокрутки, включая раскрытые карточки оценок и страницу 404.
4. Сотрудник деканата перенаправляется из кабинета студента, API отвечает 403.
