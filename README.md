# MGIMO Campus — «Цифровой деканат будущего»

Конкурсный прототип личного кабинета студента для номинации «Вайб-кодинг» MGIMO AI Challenge 2026.
**Неофициальный сервис.** Все имена, оценки, расписание и документы вымышлены. Официальная символика вуза не используется.

**Прототип:** https://153-51-170-126.sslip.io (логины и пароли жюри передаются через конкурсный кабинет).

Главный экран — «Сегодня»: следующая пара в виде посадочного талона, переносы, ближайший дедлайн, статус заявки и непрочитанные сообщения деканата. Из уведомления о переносе студент одним касанием попадает к этому занятию в расписании.

## Стек

- **Backend:** Python 3.13, Flask 3.1, SQLAlchemy 2.1 + Alembic, PostgreSQL 17, Argon2id, Flask-WTF (CSRF), Gunicorn.
- **Frontend:** React 19, TypeScript, Vite, Tailwind CSS 4, TanStack Query, React Router. Шрифты Onest и Unbounded лежат на нашем сервере.
- **Тесты:** pytest на настоящем PostgreSQL, Playwright в установленном Google Chrome.

Один адрес для страниц и API: Flask раздаёт собранный интерфейс и `/api/*`. Это упрощает cookie и CSRF и не требует CORS.

## Запуск локально

Нужны Docker, Python 3.12+, Node.js 20+.

```bash
docker compose up -d
```

```bash
cd backend && python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt
```

```bash
flask db upgrade && flask seed
```

Пароли демо-аккаунтов сервер генерирует сам и кладёт в `backend/instance/demo_credentials.json`. Этот файл не попадает в Git. Можно задать пароли заранее через переменные `DEMO_PASSWORD_*` (см. `.env.example`).

```bash
cd ../frontend && npm install && npm run build
```

```bash
cd ../backend && flask run --port 5001
```

Откройте http://localhost:5001. Порт 5000 на macOS занят системной службой AirPlay, поэтому 5001.

Для разработки интерфейса с горячей перезагрузкой: `npm run dev` в `frontend/` (http://localhost:5173, `/api` проксируется на 5001).

## Тесты

```bash
cd backend && . .venv/bin/activate && python -m pytest
```

```bash
cd frontend && npm run e2e
```

pytest пересоздаёт схему в базе `campus_test`, e2e — в базе `campus_e2e`. Рабочая база `campus` не трогается.

## Размещение

Сервер: Yandex Cloud, Ubuntu 24.04, 2 vCPU (20%), 2 ГБ RAM. На нём Caddy (HTTPS от Let's Encrypt), Gunicorn, PostgreSQL 16, резервная копия базы дважды в сутки (хранится 7 дней на том же диске) и ежедневное обновление демо-событий.

```bash
bash ops/deploy/deploy.sh
```

Скрипт собирает интерфейс, при первом запуске настраивает сервер (`ops/deploy/server_setup.sh`), копирует код, ставит зависимости, применяет миграции, при пустой базе засевает демо-данные и проверяет `https://<адрес>/api/health`. Пароль базы и `SECRET_KEY` создаются на сервере в `/etc/campus/campus.env` и в репозиторий не попадают. Доступ — по SSH-ключу `~/.ssh/mgimo_campus_deploy`; адрес и пользователь — в `ops/deploy/config.sh`.

Пока нет своего домена, сайт работает на имени `153-51-170-126.sslip.io`: оно указывает на IP сервера и позволяет получить сертификат.

Проверка размещённой версии теми же сквозными тестами (после них демо-данные пересоздаются с прежними паролями):

```bash
bash ops/deploy/check_production.sh
```

Пароли демо-аккаунтов размещённой версии после первой выкладки лежат в `backend/instance/production_demo_credentials.json` (вне Git).

## Защита данных простыми словами

- Пароли хранятся только в виде хеша Argon2id с солью.
- После входа браузер получает подписанную cookie со случайным идентификатором. JavaScript её не видит (HttpOnly), на чужие сайты она не уходит (SameSite). Выход отзывает сессию на сервере.
- Каждый изменяющий запрос требует CSRF-токен.
- Сервер сам определяет, кто вошёл, и выдаёт только его данные. Чужая заявка, уведомление или занятие чужой группы по прямому адресу отвечают «не найдено».
- После пяти неверных паролей подряд вход для этого логина приостанавливается на 10 минут.
- Ошибки сервера не показывают технических подробностей.
